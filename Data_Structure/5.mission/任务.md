明白了，你说得很清楚。你设计的是**任务的叙事锚点**，而不是一个包含所有分支的完整剧本。具体战斗怎么打、检定怎么投，都交给各自独立的模块去处理。`mission` 只负责三件事：**何时触发、讲什么故事、标记状态**。

## 关于“结束”与“完成”的拆分

你提出的区分很有道理，在城主手册的框架下确实应该分开。我建议使用两个独立的布尔字段：

| 字段 | 类型 | 含义 |
| :--- | :--- | :--- |
| `is_completed` | boolean | 玩家**达成了任务目标**（打败了哥布林大王、交付了物品）。完成意味着正面结果。 |
| `is_ended` | boolean | 任务**已关闭，无法再触发**，无论是否完成。比如时限到了、关键 NPC 死了、村庄被毁了。 |

两者的关系：

- 通常 `is_completed: true` 会将 `is_ended` 也视为 `true`
- 但 `is_ended: true` 时 `is_completed` 可能仍是 `false`
- 程序逻辑可以这样处理：`is_ended` 为真时，任务不再出现在可用列表中；但后续剧情可以根据 `is_completed` 的状态给出不同走向

这与城主指南中“故事遭遇”的设计一致：失败也是一种叙事推进，不是死胡同。

## 修正后的推荐字段

基于你的反馈，去掉所有战斗数据、检定数据和过度结构化的内容。最终建议就这些：

| 字段 | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `mission_id` | string | ✅ | 唯一标识 |
| `name` | string | ✅ | 任务名称 |
| `type` | array of string | ✅ | 标签，如 `["combat"]`、`["exploration"]`、`["social"]` |
| `is_triggered` | boolean | ✅ | 是否已经触发过 |
| `is_repeatable` | boolean | ✅ | 是否可以反复触发 |
| `trigger_condition` | object | ✅ | 包含两个子字段（见下） |
| `npc_involved` | array of string | 否 | 涉及的关键 NPC ID |
| `content` | string | ✅ | 一句话描述这个情节是什么 |
| `is_completed` | boolean | ✅ | 是否已达成任务目标 |
| `is_ended` | boolean | ✅ | 是否已关闭（无法再触发） |

**`trigger_condition` 子字段**

| 子字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `required_missions` | array of string | 需要先完成的任务 ID |
| `other_conditions` | string | 用自然语言描述的其他条件，交给 AI 自行判断。例如：“持有火把、提灯或其他照明工具，或队伍中有角色能施展产生照明的法术” |

## 示例

```json
{
  "name": "剿灭哥布林大王",
  "mission_id": "mission_defeat_goblin_king",
  "description": "",
  "type": ["combat"], // exploration, combat
  "is_triggered": false,
  "trigger_condition": {
    "required_missions": ["mission_find_cave_entrance"],
    "other_conditions": "持有火把、提灯等照明工具，或队伍中存在能够使用照明魔法或戏法的角色"
  },
  "npc_involved": ["npc_goblin_king"],
  "combat_involved": [""],
  "content": "深入哥布林洞穴最深处，找到并击败哥布林大王，终结它对村庄的威胁。",
  "is_completed": false,
  "completed_conditions": "",
  "is_ended": false,
  "ended_conditions": ""
}
```

这个结构只负责叙事层面的触发和状态记录。AI 城主读取后，知道“这里可以有什么故事、需要什么条件、现在是什么状态”，然后自己调用战斗模块、检定模块去处理具体执行。

如果在设计过程中，你对某些任务的 D&D 规则判定拿不准（比如某个任务适合设定什么 DC、应该引用哪个怪物数据块），随时可以问我。
