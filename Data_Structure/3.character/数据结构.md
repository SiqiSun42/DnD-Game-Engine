不完全是，取决于你想改的是哪一类东西。

## 只改 UI 文件夹、且**不必动**数据层的情况

**纯样式** → 只改 CSS 即可：
- 栏宽比例（如人物 `1:2:2`）
- 字号、颜色、间距
- 标题下划线、表格样式等

对应文件：`UI/css/panels/*.css`

**展示逻辑**（在数据已经准备好的前提下）→ 只改对应 **panel 的 js**：
- 哪些字段要显示 / 隐藏
- 显示顺序、中文标签
- 「未解锁 🔒/🔑」这类规则
- 空状态文案

对应文件：
- `UI/js/panels/character-panel.js`
- `UI/js/panels/backpack-panel.js`
- 等

**分类名称、顺序** → 改 schema，不动数据加载：

- `UI/data/ui-schemas/panels.json`

---

## 需要动「数据提取」层的情况

如果 JSON **新增了字段**，或 UI 需要 **JSON 里没有、要算出来的值**，就要改 utils：

| 文件 | 职责 |
|------|------|
| `inventory-utils.js` | 读 list/all、拼物品对象、负重/金钱累加 |
| `character-utils.js` | 读人物 bundle、筛 pc/ally |
| `derived-state.js` | 跨模块派生值（给 AI 用） |
| `game-data.js` | 存档加载、面板取数入口 |

例如：人物 JSON 多了 `title` 字段 → 先在 `character-utils.js` 的 `buildUiCharacter` 里带上，再在 `character-panel.js` 里渲染。

## 你们现在的分层（简化）

```
Data/Saves/.../json          ← 只存原始数据
        ↓
*-utils.js + derived-state   ← 读取、合并、计算（给 UI/AI 用）
        ↓
game-data.js getPanelData()  ← 入口
        ↓
panels/*.js                  ← 渲染什么、怎么排
        ↓
css/panels/*.css             ← 长什么样
```

**经验法则：**
- 改「长什么样」→ CSS
- 改「显示什么、怎么组织」→ panel js（数据已在 `char` / `item` 上）
- 改「数据从哪来、多一个新字段」→ utils
- 改「存档怎么读」→ game-data.js

所以：**很多 UI 调整确实可以只动 `UI/` 里的 panel + CSS**；只有 JSON 结构变、或要新派生字段时，才需要动 utils。你们现在的拆分已经按这个思路在做。
