**修改点总结**

| 原字段名 | 新字段名 | 变化 |
|----------|----------|------|
| `涉及人物` | `关联人物` | `角色`改为`简述`，自由描述该人物与事件的关系 |
| `涉及组织` | `关联组织` | 同上 |
| `涉及地点` | `关联地点` | 同上 |
| `涉及事件` | `关联事件` | 保留`关系`字段，同样为自由文本 |

这样无论事件是战争、瘟疫、政变、宗教会议还是自然灾害，`简述`字段都能灵活描述关联实体与事件的关系，不受固定标签的限制。

你这个“未开始事件”的设计非常棒。它让事件从“历史记录”和“正在发生的事”扩展到了“可能发生的未来”，这正是 D&D 中“冒险引子”的核心——玩家的行动可以阻止灾难，也可能触发更大的危机。

**完整字段设计**

| 模块 | 字段 | 类型 | 说明 |
|------|------|------|------|
| **状态标记** | `是否开始` | 布尔值 | 事件是否已经开始。`false` 表示尚处于潜伏/未触发状态 |
| | `是否结束` | 布尔值 | 事件是否已经结束。进行中的事件为 `false` |
| **时间与条件** | `开始条件` | 对象或 null | 事件触发的具体条件，`是否开始: false` 时必填；已开始时可留 null |
| | `开始时间` | 字符串或 null | 若已开始，记录开始时间；若未开始，可为预计时间或留 null |
| | `结束时间` | 字符串或 null | 若已结束，记录结束时间；进行中则为 null |
| **结果描述** | `结局` | 字符串或 null | 已结束事件的真实结局。进行中或未开始的事件为 null |
| | `可能结局` | 数组 | 未结束事件可能走向的多个结局描述，每个包含触发条件和结果概述 |

**设计要点**

1. **`开始条件`** 是一个灵活的对象，包含触发方式，以及玩家可以提前阻止它的行动。这给了城主清晰的判定依据，也给了玩家“改变未来”的机会。
2. **`可能结局`** 用于描述事件的不同走向。每条结局都有明确的触发条件和结果，确保无论玩家选择哪种行动路径，城主都有剧本可依。事件结束后，选中的结局可以写入 `结局` 字段。
3. **`影响`** 数组在事件进行中或结束后才填充，未开始的事件可保持为空——因为变化尚未发生。
4. 这样设计之后，面板就可以动态地展示“这个事件可能何时发生、怎样能阻止、结果会怎样”，让世界真正地活起来，而不再是静态的百科词条。
