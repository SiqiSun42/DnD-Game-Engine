## 层级
两层目录，可折叠，通过”返回上一级“和”进入下一级“切换。默认从第二级展开。

### 第一层
位面 → 世界 → 大陆 → 国家

### 第二层
地区 → 城镇 → 场所 → 房间

## 玩家当前位置
默认从玩家当前位置展开。当前位置的最大级别是城镇，换言之，当前位置只有城镇、场所和房间三个选项。地区及以上层级视为不可交互。

**几点说明：**

- **位置**：使用了之前讨论的“楼层 + 方位 + 编号/地标”描述方式。
- **人物**：数组，每个元素只有名称和描述，招募/死亡后直接移除。
- **出口**：每个出口包含目标、状态（敞开/关闭/上锁/隐藏等）、可选检定和备注。
- **服务**：效果用文字描述（如“完成一次长休”），价格使用标准 D&D 货币。
- **库存**：这里用文字说明链接方式，实际实现时可能是一个外键或字符串标识。
- **重要物品**：区别于库存，包含隐藏位置和发现检定。
- **情节**：包含了触发条件和是否可重复，后续可扩展。
- **特性** 和 **可执行动作** 已留空数组，等你进一步讨论时再定义具体格式。

## 其他层级
不同层级需要不同的字段。

---

**字段在各层级的保留情况**

| 字段 | 房间 | 场所 | 城镇/大型地标 | 地区及以上 |
|------|------|------|---------------|------------|
| 位置 | ✓ | ✓ | ✓ | ✓ (仅作为分类标签) |
| 简介 | ✓ | ✓ | ✓ | ✓ |
| 地理 | ✗ | ✗ | ✓ | ✓（地区需要，更往上的分类不需要） |
| 文化 | ✗ | ✗ | ✓ | ✓ |
| 光照 | ✓ | ✓ (室内场所) | ✗ (室外不适用) | ✗ |
| 安全/隐蔽 | ✓ | ✓ | ✓ | ✗ |
| 人物 | ✓ | ✓ | ✓ | ✗ (重要NPC独立管理) |
| 出口 | ✓ (通往相邻房间) | ✓ (通往相邻场所或城镇) | ✓ (通往相邻城镇或地区) | ✗ |
| 服务 | ✓ | ✓ | ✓ | ✗ |
| 库存 | ✓ | ✓ | ✓ | ✗ |
| 情节 | ✓ | ✓ | ✓ | ✗ (太宏观) |
| 特性 | ✓ | ✓ | ✓ (如整片荒野被诅咒) | ✗ |
| 可执行动作 | ✓ | ✓ | ✓ (如城门哨卡盘问) | ✗ |

**场所**基本可以完全照搬房间模板，只是有些字段（如光照）对室外场所可能不适用。

**城镇/大型地标**则保留绝大多数字段，不过“光照”对户外城镇也基本不需要。城镇和地区需要描述地理特征，例如平原、山地，但更大的区域则不需要。

**地区及以上**，保留位置、简介即可。地区是纯导航标签，不需要任何互动字段。

---

**距离字段的设计**

在 D&D 规则中，距离是计算旅行时间的基础。《玩家手册》明确指出，队伍的**每日行进速度**取决于最慢成员的移动速度（通常为 24 英里/天，步行），而《城主指南》的随机遭遇也依赖距离来决定每段旅程的遭遇检定次数。

因此，**距离应该放在“城镇/大型地标”层级和“地区”层级**，不同的层级计算方式不同：

- **城镇与城镇之间**：需要大地图距离。从一个聚落到另一个聚落，这段距离决定旅行需要几天、消耗多少补给、经历几次随机遭遇。距离可以放在“出口”字段里——当城镇 A 的出口指向城镇 B 时，出口不再是简单的“敞开/关闭”，而是附带距离和旅行难度。

- **场所与场所之间（在同一个城镇内）**：可以不记距离，因为城里移动最多花费几小时，除非你的游戏有严格的城内探索规则。如果需要，也可以在场所层级的“出口”里附带距离。

- **房间与房间之间**：一般不需要距离。D&D 中房间之间的移动是即时的（除非是超大型地下城），需要记录的只是“相邻关系”。

**建议的出口字段扩展：**

对于**城镇/大型地标**层级，出口结构可以这样设计：

```json
{
  "出口": [
    {
      "目标": "博德之门",
      "距离": 120, // 单位英里
      "地形": "平原",
      "路径描述": "沿剑湾商道向北，经过几个小村庄。"
    },
    {
      "目标": "巨魔之山",
      "距离": 40,
      "地形": "山地",
      "路径描述": "向东穿过森林边缘，然后攀上陡峭的山路。"
    },
    {
        "目标": null, // null 表示死路
        "距离": "15 英里",
        "地形": "森林",
        "路径描述": "一条被密林遮蔽的蜿蜒小径，入口处杂草丛生，似乎少有人走."
    },
  ]
}
```

这样，系统就可以读取距离字段，按照《玩家手册》的旅行规则自动计算耗时（比如 120 英里 ÷ 24 英里/天 = 5 天），并根据地形决定遭遇检定频率。

**对于场所层级**（在同一个城镇内），出口可以简化：

```json
{
  "出口": [
    {
      "目标": "光辉之锤铁匠铺",
      "距离": 10, // 步行x分钟
      "路径描述": "从酒馆出门左转，走到街角就是。"
    },
    {
      "目标": "海港区码头",
      "距离": 30, 
      "路径描述": "穿过市集广场，沿着主路一直向南。"
    }
  ]
}
```

**对于房间层级**，出口保持现有设计（相邻房间，无距离或短距离）。

---

**总结：**

-   场所和城镇的字段可以高度复用房间模板，个别字段增删即可。
-   地区及以上只需“位置”和“简介”。
-   距离信息放在“出口”字段里，随层级不同而详细程度不同：房间出口不记距离，场所出口可记步行时间，城镇出口记英里数和地形，方便系统自动计算旅途耗时。
